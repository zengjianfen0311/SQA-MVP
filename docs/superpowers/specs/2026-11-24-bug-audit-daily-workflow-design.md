# Bug 审计每日工作流设计

状态：已批准。阶段 A 已完成并通过 Bug 审计专属离线验收；阶段 B 已更新既有 Codex automation 提示词，等待后续真实日常运行核对。

## 意图

将 Codex 定时任务“固件Bug每日审计回填与飞书通知”的每日运行结果纳入 SQA-MVP 的“Bug 审计”模块，形成可查询、可恢复、可核对的审计运行台账。Codex 继续负责 19:30 触发、语义审计和调用既有 TP/飞书通道；项目负责持久化运行、Bug、逐字段结论及副作用回执，并在 Bug 审计页面展示闭环状态。

## 当前行为

- 项目现有 Bug 审计读取已发布的 TP 快照，计算 RID 缺陷统计，提供状态和文本筛选、人工复核及创建整改任务。
- 项目自动更新只读 TP 快照或受控本地文件，不读取每日 Bug History，不写 TP 审计字段，也不发送飞书通知。
- 定时任务按北京时间每天 19:30 执行。范围为 Suunto work 项目及既定固件团队，包含所有状态；窗口为当天 00:00（含）至本次启动时间（不含）。只纳入窗口内 State 或 Severity 存在真实旧值到新值变化的 Bug；Add 初始化不算变更，按 Bug ID 去重。无法判定时保留 partial，不猜测。
- 审计结果分别判断 Bug Standard Review of Testing、Bug Standard Review of Development、Bug quality audit 三字段。字段只有证据完整且 ready 才能写；写前在线复核原值与业务状态，冲突时不覆盖；写后逐字段回读。操作范围不扩展到状态、Severity、Developer、Relations、Feature 等业务字段。
- 飞书通知继续使用现有机器人、目标群、真实提及、附件、幂等键和发送后回读规则。不得把原始评论、敏感标识、凭据或本地绝对路径发到群里。

## 目标

- 每个本地日期和范围只建立一个可恢复的审计运行；重跑时续接记录，不重复建立运行或重复登记成功的副作用。
- 持久化实际时间窗口、范围完整性、候选 Bug、命中的 History 标识和旧/新值、证据层完整性，以及三字段各自的原值、拟值、ready 状态和原因。
- 逐字段记录预检、冲突、写入尝试、未知结果、回读值及最终状态；字段级部分成功不得覆盖成整单成功。
- 记录通知摘要、附件摘要、目标和发送回执，使“审计完成”“TP 回填完成”“飞书发送完成”可以分别核验。
- 在现有 Bug 审计页面查看运行列表、部分/失败状态、按 Bug 展开的字段结论和证据定位。

## 非目标

- 不改变 PR 审计、指标治理、资料库、崩溃专项、通用批次导入/自动更新、账号/任务等独立模块的行为。
- 不把定时任务改成服务内调度器；第一阶段继续由现有 Codex 定时任务触发。
- 不把 DataBridge 改造成写入器，不让 Web 服务保存 TP token、飞书凭据或用户 Cookie。
- 不扩大当前日期窗口、项目/团队范围、三字段授权、通知对象或发送身份，不自动更改普通 Bug 状态及其他 TP 字段。

## 方案选择

1. 全部迁入 SQA 服务：定时、审计、TP 写回和飞书通知由后台服务执行。运行集中，但扩大服务凭据与可用性责任，也改变现有定时任务的执行边界。
2. Codex 触发 SQA 台账：保留现有 Codex 调度和外部操作，项目只新增运行记录与展示。迁移最小，但项目不会独立承担写入与通知执行。
3. 分阶段混合（已选）：Codex 继续触发、取证、语义审计并使用既有 TP/飞书操作通道；项目以 Bug 专属 CLI 导入每一步的结构化结果、持久化副作用回执并展示。先完成离线记录与恢复，再让现有自动化登记它已经完成的回填和通知结果；不迁移调度器，也不让项目发起或控制外部副作用。

## 设计

### 模块边界

- 新增 `outputs/SQA_MVP/bug_audit.py`，承载 Bug 审计运行数据模型、状态迁移、幂等记录、字段级并发冲突状态和查询投影。复用 `Store.connection()` 的事务，不修改通用 `store.py` 表或 `imports.py` 解析逻辑。
- 新增 `outputs/SQA_MVP/bug_audit_cli.py`，提供仅本机调用的 `begin`、`record-evidence`、`record-findings`、`record-writeback`、`record-notification`、`complete` 等命令。命令接收显式 `--data-dir` 与 UTF-8 JSON 文件，不接收凭据参数；输入必须校验运行 ID、Bug ID、字段白名单和 schema 版本。
- `app.py` 仅增加 Bug Audit service 初始化及 `/api/bug-audit/*` 读取路由，沿用现有登录态、角色和 Host 校验。运行结果仅负责人及协同审核角色可见；现有 Bug 行列表仍按原权限执行。
- `web/app.js` 仅扩展“Bug 审计”页，增加“当前快照”和“每日审计运行”视图；不改导航结构或其他页面。运行结果先只读展示，不能从页面直接调用 TP 写接口。
- Codex 自动化提示仅在项目实现及离线验收完成后更新为“把阶段结果写入本机台账并回读确认”；原调度时间、业务口径、TP/飞书身份和操作规则保持不变。此次设计阶段不修改自动化。

### 持久化对象

- `bug_audit_runs`：幂等运行键、规则版本、Asia/Shanghai 日期窗口、范围配置摘要、采集/审计/回填/通知各阶段状态及摘要计数。
- `bug_audit_items`：每个运行内去重 Bug 的当前快照、纳入原因、命中 History ID/时间/字段/旧新值、各证据资源的 complete/partial/failed/not_requested 状态。
- `bug_audit_fields`：每 Bug 每审计字段一行，保存原值、拟值、ready、阻塞原因、预检值/冲突、写入状态和回读值。拟值 `null` 表示不写，禁止解释为空字符串或清空。
- `bug_audit_events`：不可覆盖的阶段事件，包括导入摘要、冲突、写入回执、通知回执和人工恢复操作；敏感凭据绝不落库。
- 外部内容只保存完成审计所需的脱敏证据摘录或资源定位，不保存整批原始评论。完整审计证据仍由本次运行目录依现有保留策略管理。

### 调用链

1. 19:30 Codex 自动化开始本地运行目录，按现有规则通过 DataBridge 只读取数和筛选 History，再完成人工语义审计；外部 TP/飞书动作仍走现有已验证通道。
2. 自动化把每阶段结构化 JSON 传给 Bug Audit CLI。CLI 用 `run_key = 日期 + 规范化范围摘要 + 规则版本` 创建或恢复运行；重复导入通过事件 ID/内容哈希识别，不重复计数。
3. `bug_audit.py` 校验范围窗口、History 真实值变化、Bug 唯一性、字段白名单及 ready 约束，以 SQLite 事务写入运行台账。缺证据和无法解释的字段标为 partial/pending，不伪装成空结果。
4. 实际 TP 写入前，自动化先在线复核三个字段、选项及业务状态。仅对 ready 且原值未变化的字段逐字段写入；未知请求结果先回读，绝不盲目重发。之后把逐字段结果和回读值提交 CLI。
5. 通知使用当次稳定幂等键；发送后回读消息并提交 message/chat 标识、正文摘要和附件校验结果。结果未知先核验，部分成功只补失败项。
6. UI 从 `/api/bug-audit/runs` 与 `/api/bug-audit/runs/{id}` 读取台账，并将采集、审计、回填、通知状态分别呈现。整单只有全部适用阶段均核验通过才标 complete；否则显示 partial、blocked 或 failed 和原因。

### 阶段交付

- 阶段 A：CLI 与 SQLite 台账、离线样例和 Bug 审计页只读展示；由模拟输入验证续跑、字段级 ready、partial、去重和并发冲突。此阶段不访问 TP 或飞书。
- 阶段 B：在阶段 A 验收后更新现有 Codex 自动化提示，使其按阶段把候选、审计结论、字段级 TP 写入/回读结果、飞书发送/回读结果写入台账。Codex 仍按现有顺序和工具执行所有外部动作；项目只接收及展示结果，不拦截、发起或重试外部写入。用后续真实日常运行核对台账完整性、幂等续跑和回执对账，不额外创建一份定时任务。

## 验收标准

- 隔离数据库中，同日重跑恢复同一 run；重复 Bug、重复 History、重复事件不增加计数或重复副作用。
- 候选窗口按北京时间左闭右开；Add、仅其他字段变动和同值更新不纳入；状态或 Severity 任一真实变化纳入一次；缺少关键 History 时范围标 partial。
- 三个字段分别计算 ready；某字段 pending 不阻止其他 ready 字段，但不得写入 pending/null 字段。
- 预检发现原值变化时进入 conflict 且不发送写请求；写入超时先回读；写后逐字段精确回读；不得影响其他 Bug 字段。
- 飞书部分发送、超时未知、附件不匹配和回读失败分别可恢复；已确认成功的消息不能重复发送。
- UI 显示运行窗口、范围完整性、三个字段状态、审计/回填/通知分项结果；没有凭据、评论全文或敏感数据出现在日志和群通知中。
- 变更文件限定在 `bug_audit.py`、`bug_audit_cli.py`、`app.py` 的 Bug Audit 路由、`web/app.js` 的 Bug 审计页面及其专属测试/设计文档；阶段 B 仅更新现有 Codex 自动化中与写入台账相关的指令，保留其调度、外部写入顺序、身份和目标不变。TP 与飞书 live 测试须显式 opt-in，默认测试仅使用模拟适配器。

## 仍由实现者决定

- run 与 evidence 表的具体列、索引及 JSON schema 版本。
- CLI 输入文件的具体分阶段格式和错误恢复码。
- Bug 审计页内采用标签页还是同页时间线呈现运行记录。
- 旧快照行复核与每日审计记录的 UI 关联方式；两类结论保持独立，避免把旧的单值人工复核误显示为每日三字段回填结果。
