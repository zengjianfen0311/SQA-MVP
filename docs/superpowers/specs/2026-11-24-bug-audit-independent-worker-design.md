# Bug 审计独立 Worker 设计

状态：用户于 2026-11-24 明确确认并批准；实施方式沿用 Native。

## 用户已确定的目标

- 采用“独立 Worker + 现有 Web 台账”，没有安装 Codex 的电脑也能完成真实审计。
- 语义审计使用公司现有模型服务；地址、协议类型、模型名和密钥通过部署配置提供。
- 仅修改 Bug 审计及其专属配置、依赖、测试、文档；其他独立功能模块禁止修改。
- 沿用既有固件范围、日期窗口、审计规则、三个可写字段、TP 身份和通知目标。飞书身份按下述用户最新授权执行，既有授权不因换执行器而扩大。

本文替代上一版设计中“项目只记录结果、外部动作全部由 Codex 执行”的边界：新 Worker 可以执行已配置、已授权的取数、模型审计、三字段回填和通知。Web 仍只读展示审计运行，不持有 TP、飞书或模型凭据，不新增网页写回按钮。现有 Codex 任务在切换前继续保留，本设计阶段不暂停、不改调度、不启动新执行器。

## 目标与非目标

干净克隆后，安装声明的依赖即可完成自检、合成演示及离线回归；配置部署机自己的接入后，可在 Windows、Linux、macOS 手工执行或被操作系统调度。项目运行不读取个人 `.codex`、`.agents`、旧历史目录，不调用 Codex、Lark CLI 或个人技能中的脚本。

不把真实数据、凭据或个人自动化配置提交到 Git；不把模型回复当作可执行命令；不自动修改状态、Severity、Developer、Relations、Feature 等业务字段；不提供多个独立数据库同时对同一生产范围写入的分布式保证。不在本次改动中引入任务队列、Redis、通用调度平台或重构其他页面。

## 考虑过的方案

| 方案 | 可移植能力及代价 | 结论 |
| --- | --- | --- |
| 仅补启动与演示 | 可运行页面和样例，真实审计仍依赖个人 Codex 执行器 | 不能满足最终目标 |
| 独立 Worker + 现有台账 | 仓库持有完整流程，Web 沿用现有模型；外部凭据仅由 Worker 持有 | 用户已选 |
| 把调度和所有操作放入 Web | 部署入口少，但扩大 Web 的凭据和副作用职责，并改变现有服务边界 | 本轮不采用 |

## 结构与技术选择

以下是实现者提出的默认选择，供用户审阅：保留 Python 3.11+，使用标准库 HTTP、SQLite 和 TOML 配置；明确声明时区数据依赖。新增 `outputs/SQA_MVP/bug_audit_worker/` 专属包、`bug_audit_worker_cli.py` 入口、专属依赖声明、配置模板、版本化规则和提示词、合成样例及使用文档。精确文件拆分和函数签名留给实施计划。

调用链为：手工/操作系统调度/Codex 可选触发 → Worker 协调器 → TP 采集 → 确定性事实与规则 → 公司模型语义审计 → 三字段结论与审计计划 → 在线预检及受控写回 → 回读 → 飞书通知及附件核验 → 本机对账 → 现有台账与只读 Web。

| 部件 | 职责 |
| --- | --- |
| 配置与 doctor | 配置校验、路径解析、依赖/权限/时区自检；在线探针必须显式启用 |
| TP 只读适配器 | 项目/团队/选项元数据、候选、History、评论、Relations、必要 Feature 的有界分页与批量获取 |
| 规则与事实层 | 日期窗口、真实变更、首次响应计时、关系方向、已确定字段约束和选项映射 |
| 模型适配器 | 仅向配置的公司服务提交必要证据，返回结构化语义判断与证据引用 |
| 协调器与检查点 | 运行身份、阶段状态、源证据摘要、预算、失败恢复、锁与副作用台账 |
| TP 写回适配器 | 三字段白名单、逐字段预检、请求登记、实际写入与回读；与只读适配器分离 |
| 飞书适配器 | 机器人认证、目标与成员核验、真实提及、消息/附件发送、回读和下载哈希核对 |
| 报表与对账 | 审计报告、脱敏 CSV、阶段结果和逐项台账对账 |

原 DataBridge 和审计技能是已验证契约与规则的参考来源，不作为运行依赖，也不将 DataBridge 改成写入器。可复用的纯规则应迁入仓库并带测试和来源/规则版本；不得导入固定历史日期、Bug ID、人工结论、`.env` 或旧脚本的机器路径。新 TP 适配器只实现本工作流实际需要的能力，不复制整个个人工具目录。

## 配置与无 Codex 部署

配置至少包含：执行配置身份、数据/运行目录、Asia/Shanghai 时区、TP 域名及项目/AssignedTeams、规则版本、模型协议/base URL/模型名、飞书机器人应用 ID/目标群/提及对象、HTTP 超时/重试/分页限制、模型与运行预算。

凭据配置只保存环境变量名称，例如 `tp.token_env`、`model.api_key_env`、`feishu.app_secret_env`；密钥由部署机环境或其密钥管理机制提供。不自动寻找原机器 `.env`，不回退到个人登录态，也不把令牌写入参数、台账、日志或报告。所有配置内相对路径以配置文件目录为基准解析，启动工作目录改变不影响结果。Web 与 Worker 必须显式指向同一个数据目录，初始化不覆盖已有用户或业务数据。

统一入口计划提供：`doctor`、`demo`、`run`、`resume`、`reconcile`。精确命令名可由实施计划确定，但必须具有以下语义：

- `doctor` 默认离线；显式在线检查只进行认证/元数据读取和不含业务资料的模型合成探针，不发送群消息或写 TP。
- `demo` 使用仓库合成数据和模拟适配器，无任何网络或真实凭据依赖；生成独立目录并可从 Web 查看。
- `run` 默认只读分析：允许显式在线采集和公司模型审计，生成计划与台账，禁止真实回填或通知。执行外部写入必须由命令和执行配置明确选择 apply 模式。
- `resume` 恢复同一检查点和冻结窗口；不能重新计算截止、重审覆盖已确认副作用或盲目重发。
- `reconcile` 回读当前台账及已有检查点；在线回执核验需显式选择，只读查询/下载，不创建新消息或写 TP。

演示、只读分析和 apply 必须在运行身份及 Web 详情中明确区分。运行键包含本地日期、规范化业务范围、规则摘要、执行配置身份和模式；演示不能冒充真实记录，只读分析不能自动升级成已授权写入。可将只读计划作为 apply 输入，但 apply 创建独立执行记录、保留计划来源与冻结窗口，并重新核验实时证据；不得直接执行陈旧计划。

首版使用操作系统调度器调用一次性 Worker 命令，提供 Windows 与 POSIX 示例，不内置长期驻留调度器。调度时间默认沿用北京时间 19:30，不能用主机默认时区替代。示例不自动安装调度或复制本机任务。

## 范围与取证

默认部署模板可包含当前项目/团队配置的示例说明，但真实域名、身份、群和凭据必须由部署者明确填写；本机现行配置作为独立忽略文件保存，不硬编码在代码或测试中。

生产当前口径仍为 Suunto work 项目、三个既定固件 AssignedTeams、所有状态和创建年份。当天窗口为北京时间 00:00（含）至首次运行冻结时刻（不含），保留毫秒/微秒。同一执行模式下同日同范围同规则恢复同一运行。modifyDate 只作候选下界，不能代替 History。

候选须按分页数量、实际返回和结束原因核验。窗口 History 如无直接旧值，需读取足够的前置历史/快照计算旧新值；不能只因 changes 列出了字段就纳入。Add 初始化、同值变化、仅其他字段变化均排除；State 或 Severity 任一真实变化即可纳入，每个 Bug 一次，History 按 ID 与字段共同去重。无法核实则范围 partial，不退回全库、不猜测排除。

对最终 ID 集批量读取完整有效评论、首次响应所需完整历史、真实 Relations 及目标实体类型、必要 Feature 元数据/描述、当前三个审计字段与在线选项。各资源分别记录 complete/partial/failed/not_requested；分页不完整、上下文预算不足或解析失败不能转为空数组。历史窗口、项目范围和资源读取结果均保留可审计依据。

## 规则与公司模型

将用户当前确认的规则 2026-11-10 纳入版本管理，记录内容哈希；后续规则变化产生新版本，不依赖个人技能文件在运行时自动变化。保留旧单 Testing 只选 No need、首次 Severity 修改决定首次响应阈值、北京时间剔除周末、真实 Relations 方向、REG 条件必填、当前问题与历史问题区分、Developer 交接旧规则已取消等口径。

模型用于提单信息在正文/评论中的覆盖、当前状态说明、关键词语义、Feature 用户功能匹配等确定性代码无法可靠完成的部分。模型输出应按检查项提供 pass/fail/pending/not_applicable、理由和来源证据定位；三字段拟值与 ready 由规则汇总器形成，模型不能直接调用网络、写台账或提交 TP/飞书请求。

首版支持显式选择的公司 OpenAI 兼容 Chat Completions 或 Responses 协议；模型名和上下文上限由部署配置给出。使用无工具调用的独立请求，不依赖 Codex 会话、previous_response_id 或工具调用续传。结构化输出能力由合成 doctor 探针验证；不支持服务端 JSON schema 时须显式配置兼容模式，并仍做同等本地严格结构/选项/引用校验，不自动悄悄切换协议或公开云端服务。

向模型提交前剔除凭据、邮箱、设备敏感标识和无关日志，并记录脱敏/覆盖依据。标题、正文、评论和模型响应都作为不可信资料；其中的指令不授予权限，模型引用必须指向本次已读取的证据，不接受伪造 ID 或空引用的通过结论。结构合法只证明格式，不能代替语义质量验收。

每个 Bug 必须覆盖全部有效评论及适用检查；不能为适应上下文只取前 N 条。超出预算时可以分段检查并按证据覆盖合并，无法证明全覆盖的受影响字段 pending；不得静默截断或当作通过。模型拒绝、超时、缺引用、无效选项或不确定时，只阻塞对应字段；独立确定性结论仍可保留。不以模型自报的高置信度替代证据完整性。

## 写回、通知与恢复

Worker 只允许三个既定审计字段，null 表示不写。写前在线复核业务状态、当前团队、评论、Relations、选项及原值；资料变化时重新核验受影响结论，原值冲突则跳过，不能覆盖他人新增结论。Testing/Development 按多选选项语义比较，文字字段精确比较，保存实际原值与回读原文。

沿用已验证的 TP 三字段 bulk 契约，不能整对象回写。将请求内容哈希、逐字段意图、调用前状态、实际结果、回读和其他业务字段保留情况持久化。TP 无原子条件写时，写前预检不能保证消除预检至写入之间的所有竞态；保持小批次、紧邻写前读取和写后核验，不宣称原子 compare-and-swap。

通知沿用配置的机器人和群。发送前核验群及机器人身份、成员和提及对象；摘要与脱敏 CSV 分别登记稳定幂等键、消息 ID、文件哈希。正文必须产生真实提及，发送后回读身份、目标、正文、附件，并下载校验附件内容。不能退回个人账号、私聊或其他群。

2026-11-25 用户明确授权“改用当前已配置机器人”：新 Worker 使用“肖强的飞书助手”（`cli_aa6af9e3f6b9dc0d`），替代旧日报的“NG3平台 Bug洞察”（`cli_aae00437f9f89cdd`）。目标仍为 AQS，提及对象仍为肖强，open_id 按新应用作用域校验。旧消息继续以原发送者核验；新通知必须匹配新应用，不能为兼容旧消息而放松发送者检查。该身份授权不等于已完成真实发送或生产切换。

首版 Worker 使用机器人应用凭据，不依赖原 Lark CLI 保存的个人 OAuth。当前旧流程曾借助已授权用户身份只读核验群成员，该会话不会随代码迁移；若配置的机器人缺少必要群成员读取权限，doctor 明确列出缺失项，通知阶段 blocked，需应用管理员在部署侧配置必要权限。Worker 不自行申请权限、不静默借用个人账号，也不能因此改发其他目标；已经获得独立授权的 TP 步骤可按字段完成并保留通知未闭环状态。这里不取消旧执行器当前可用的用户只读通道，只规定新 Worker 的首版可移植认证边界。

现有台账不足以替代副作用执行日志：新增 Bug 专属持久化意图/outbox 与执行检查点，在任何请求前事务登记 prepared/in_flight，在返回及回读后登记 verified/failed/unknown。外部网络请求不得包在长 SQLite 事务中；崩溃后的 in_flight 先查已有消息或 TP 回读，禁止直接重试写入。

飞书 uuid 的服务端去重窗口只有一小时，因此不能用它冒充长期 exactly-once。持久台账长期保留已确认回执；未知发送即使超过窗口也不能仅因超时或“查不到”就重发，无法可靠确认则标 unknown 并提供人工核对信息，不声称闭环。

同一数据库、范围和执行配置只允许一个活跃 Worker；用 Bug 专属锁/租约和运行唯一键防止操作系统调度重入，恢复时核验锁持有者与检查点。团队生产只部署一个活跃执行器，共享 Web 数据库；开发机默认演示或只读分析。同一目标有多个不共享台账的 apply 部署属于不支持的部署方式，不能声称跨机器防重。

## 与现有台账的衔接

保留现有 `BugAudit` 和 CLI 接口的向后兼容；Worker 按阶段调用同一个服务，现有外部导入方式继续可用。新增执行来源/模式及 Worker 专属状态、检查点、意图等结构，均由 Bug 审计模块初始化，不修改通用 Store schema。增加字段/表需有旧库升级与备份测试。

Web 的 Bug 审计页可显示执行来源、模式和需要恢复的阶段，保持只读。demo 和只读计划明确显示演示/未执行；未收到真实副作用回执不能标回填/通知 verified。即便记录审计结论和所有适用回填均完成，只要仍有 pending/冲突/未知结果，整单保留 partial。整个过程不改变旧快照人工复核的含义。

## 交付与验收

1. 干净克隆：临时 HOME、无 Codex/Lark CLI/个人技能、空数据目录，安装已声明依赖后通过 doctor、demo、Web 台账展示及专属测试；覆盖中文空格路径、换 cwd、配置相对路径和缺时区数据提示。
2. 模拟完整链：用可检查请求的模拟 HTTP 服务完成 TP 分页/History/评论/Relations/模型/写回/飞书全流程，断言实际请求范围、字段白名单、顺序、模型负例、消息提及、附件哈希和对账结果；不能只检查函数被调用。
3. 故障恢复：在请求前后与登记前后注入中断；覆盖 TP/发送结果未知、原值冲突、附件失败、部分字段成功、同日重入、并发锁和已成功回执重放，验证不重复外部副作用。
4. 语义质量：使用脱敏、经人工核对的代表性案例，覆盖适用规则及 Feature/状态说明歧义；与现行人工审计逐项对照。31 项既有测试保留通过，格式 schema 通过不能作为语义质量通过。
5. 真实只读：用户在部署机配置公司模型与 TP/飞书认证后，显式启用在线探针和只读分析；验证范围、预算、证据完整性与方案，暂不写 TP/发消息。
6. 受控 apply 与切换：在用户已授权范围进行小范围真实写回/回读和既定通知验收。先验证 Worker，再在同一次受控切换中停止旧 Codex 执行器、启用新的操作系统调度；同一时段不能两份任务并行执行。旧任务仅保留暂停配置供恢复，恢复前先核对 outbox，不补发已确认副作用。

生产切换默认从下一个北京时间自然日开始：切换前核对旧任务当天已执行/未执行、是否仍运行及已有回执，暂停后确认无旧执行过程继续写入，再为 Worker 配置首次生产日期。首版不支持在旧任务已经产生当日副作用后，同日新建一份 apply 运行来接管；不能把“没有并发”当成“顺序执行不会重复发送”。小范围真实写验收也必须与当日旧任务的执行范围协调，先回读既有结果，不重复验收通知。旧台账和回执作为迁移依据保留，不能清空以重置幂等状态。

Windows 是当前可用主机；Linux/macOS 需要 CI 或实际主机测试，未执行的平台不能仅凭路径兼容声明为已验收。新增 CI 只运行 Bug 审计专属离线用例，无真实密钥或业务数据。完整历史跨模块验收仍受原六份样本缺失限制，不为本任务修改其他模块基线。

## 部署时必须提供、目前尚不需要贴到聊天的输入

公司模型服务的 base URL、API 协议、模型名、支持的上下文/结构化输出能力，以及部署机环境变量中的密钥；TP 域名和 token；飞书机器人应用 ID/secret、群和提及对象；生产执行节点及调度时区。缺少这些输入不阻止离线建设，但对应在线/apply 验收必须明确未验证。
