# 固件 Bug 审计规则与字段映射

规则版本：2026-11-10。来自用户已确认的固件Bug审计规则；适用新任务时沿用业务规则，范围和授权按当前任务核对。

## 时间与旧单

- 创建时间早于北京时间2026-01-01 00:00:00的Bug，Testing**只选No need**，不叠加其他项。边界当天及以后正常审提单。
- 旧单仍正常审状态流转。若首次响应超时，文字字段记录超时，Testing仍只有No need；Development不因旧单填No need。
- 创建时间无法核实则待确认。日期豁免不自动扩大看板查询范围。

## 提单质量

正文、标题及已有评论包含的信息有效，不要求重复填表；不要求固定格式、固定次数、稳定人工复现或每单都有日志/视频。按场景检查现象、环境、触发条件、预期/实际和发生情况。偶发或未复现本身不是不合格。

| 项目 | 已确认规则 |
|---|---|
| 固件、复现情况 | 字段空但正文已提供，不能判信息缺失 |
| Suunto App平台/版本 | 仅涉及Suunto App时适用；音乐App不等于Suunto App |
| Feature | 用户功能归属明确，且已核实存在匹配Feature，未关联才判缺失；不能按发生场景猜根因归属。已确认候选覆盖Bug的产品与用户功能时，采用最具体的适用候选；多个重叠候选本身不构成待确认。只有无法确认任何候选适用时保留待确认；跨功能重启/卡死且归属未明可暂不关联 |
| Bug Category | 所有Bug应分类；空值判缺失。调查初期允许Uncategorized，明确后应更新；Uncategorized不是字段缺失，需细化时记录待确认，不套缺失选项 |
| REG issue / Previously passed version | **REG issue=Yes时Previously passed version字段必填**；正文已有但字段空仍需补填，这是不重复填写通则的特定例外。非Yes不按此项判缺失；REG未知则待确认 |
| 内容冲突 | 已有但不一致，记录信息不一致，不能套信息缺失 |

## Reproduce与旧Needs info

两者同义：研发暂无法复现，需要测试继续调查；统计可归一，保留原状态，不自动改状态。

转入时需必要情况说明，内容清楚、能指导测试继续调查即可。技术判断加具体对比测试方向合格，不强制提供实际尝试记录或根因。例如“可能与手机系统及音乐App有关，请换系统和音乐App测试”合格。

此前仍适用的评论可以引用，不要求新增或重复评论，也不设机械评论时间窗口。仅“无法复现，请跟进”不足。无关旧评论或已被推翻的说明不能当当前依据；不清楚则待确认。

有评论但说明不足：只在文字写具体缺口，不选State transferred without comment。确已核实没有必要说明评论，才按该选项检查；不能把没拉数据当无评论。只审依据，不判断操作者是研发、测试或售后。

### Keywords

| 状态 | 要求 |
|---|---|
| Invalid | 评论包含invalid关键字和对应的无效判定句义，且需要无效理由 |
| Reproduce / Needs info | 评论包含复现、复测、测试，或英文reproduce/retest/test及常见词形，如reproduced、reproducing、reproduction、retested、retesting、tested、testing；英文不区分大小写 |

结合上下文，完整词匹配，不把无关日志、引用或子串命中视为通过。内容充分和关键词分别判断。未明确的同义词不机械判失败；Invalid其他语言能否替代invalid未定义。

## 首次响应

- **取提交后首次Severity修改记录的新值**：Critical 72小时，Blocking 48小时。按完整历史date+id核实真实Severity变更；后续再修改不改变阈值，当前值不能替代。完整历史确认从未修改时才沿用创建值（默认Normal），不能仅凭Add默认值跳过。
- 起点为创建时刻，终点为首次New→任何非New；Reproduce、Needs info也算非New。之后退回New不重算；仍在New计至明确的审计时刻。
- 北京时间周六周日不累计，工作日全天24小时计入，不扣夜间，不额外排除法定节假日。周末创建保留真实创建起点但周末累计为零。恰好48/72小时合格，超过才超时。
- 取值为其他严重程度暂不设时限，不凭停留较久判超时。首次Severity修改无法核实、或无法证明从未修改则待确认。
- 新单超时：Testing选Bug was not promptly transferred to developer，文字写流转超时；旧单Testing仍只选No need，文字照常记超时。
- 首次响应是固定结果，后续已处理不使其消除。其他状态及后来升级的独立时限未定义。

## Developer交接（已取消）

转Reproduce/Needs info不要求Developer改为提单人。不因为空、不是提单人、多人或缺少分配证据判问题或待确认；不再据此选择Not promptly transferred to tester或写信息不一致（Developer未改为提单人）。该选项其他适用场景尚未定义。旧规则产生的此类结论失效，其他Development检查仍需完成，不能直接整体OK。旧报告保留规则版本，不自动修改TP或重新推送。

## Relations

只检查目标实体是Bug的真实Relations，按整数比较；不是比较评论里的链接。

| 方向 | 正常 | 异常 |
|---|---|---|
| Inbound | 关联Bug ID < 当前Bug ID | ≥ |
| Outbound | 关联Bug ID > 当前Bug ID | ≤ |

确认异常选Relations is wrong，文字例如关联关系异常（Inbound 600≥500）。Request等非Bug忽略；General泛型不是Bug类型证明。未读取、方向未知、类型未知须待确认，不当空列表。

## 问题分类

Bug quality audit只写**问题类型（极短说明）**，多项中文分号分隔。不重复长分析或合格说明；全无异常且无待确认才单独写无异常。

| 类型 | 示例 |
|---|---|
| 信息缺失 | 信息缺失（固件版本、Bug Category） |
| 信息不一致 | 信息不一致（复现次数） |
| 流转说明不足 | 流转说明不足（测试下一步不明） |
| 流转超时 | 流转超时（Blocking：首次响应超48小时） |
| 状态与结论不符 | 状态与结论不符（已复现仍待复现） |
| 关联关系异常 | 关联关系异常（Outbound 499≤500） |
| 待确认 | 待确认（Feature匹配） |

同一单可多类型，汇总分别统计类型数及去重Bug数。字段选项无准确映射的已确认问题写文字，不伪造选项。单项通过不代表整侧OK；两个Review字段OK不与问题选项同选。
