所有默认测试只使用临时数据库与合成样例。样例位于 `tests/fixtures/bug_audit/`，可用独立目录演练：

python -B outputs/SQA_MVP/bug_audit_cli.py --data-dir work/bug-audit-sandbox begin --input tests/fixtures/bug_audit/begin.json

保存 `begin` 返回的运行 ID 和窗口；恢复运行时沿用返回的首次冻结截止时间。后续依次调用 `record-evidence`、`record-findings`、`record-writeback`、`record-notification`、`complete`，每次均传 `--data-dir`、`--input`、`--run-id` 和 `--event-id`。阶段 JSON 格式与对应样例一致，要求 `schema_version: 1`。不要将合成样例导入正式业务目录。

同一运行键复用原运行；同一事件 ID 和相同内容可重复导入，不增加记录。相同事件 ID 携带不同内容会被拒绝。内容变化时使用新事件 ID，并保留原检查点；登记失败只重试本地记录，不重做已成功的外部操作。

### 状态与恢复规则

- 每日窗口从北京时间零点开始，截止时间不含，保留毫秒/微秒精度。只纳入 State/Severity 的真实旧新值变化，排除 Add 初始化、其他字段和同值更新。同一 History 的两个目标字段分别保留。
- 三个审计字段分别登记 original_value、proposed_value、ready 和原因。拟值 null 表示不写入，pending 字段必须说明原因。
- Testing/Development 多选字段比较时忽略选项顺序，保留实际原值和回读原文；Bug quality audit 自由文本精确比较。
- ready 字段未完成回读时，回填保持 partial；仍有 pending 结论时，整单保持 partial。字段级核验、审计记录完成度、通知状态分别展示。
- 补录相同结论保留已有回填回执。已有写入、冲突或未知回执的字段禁止直接覆盖原结论；须先核对原检查点与真实回读证据。
- 新阶段回执使整单重新进入 running；再次调用 complete 时按当前记录重新核对，即使复用原 complete 事件也不会卡在旧状态。

### 执行器接入

本仓库提供本机台账、CLI 和只读 API，不包含独立审计 Worker、内置日程调度器或 TP/飞书写入器。已有执行器在完成取证、审计、在线预检、回填回读与通知核验后，按阶段将结果导入 CLI。个人自动化配置不属于仓库内容，部署到其他电脑时需自行接入执行器和业务身份。

CLI 不接收 TP/飞书凭据。导入 JSON 只保存必要的脱敏结构化结果，不放入完整评论、凭据、敏感标识或本地绝对路径。真实外部副作用需按部署环境已有授权执行；台账登记成功不能替代真实系统回读。

跨模块历史验收另需原有 `work/pilot-sources.json` 及六份历史源文件。路径映射模板为 `tests/fixtures/bug_audit/pilot-sources.template.json`，其中占位内容不能直接用于验收，任意新数据也不能替换原脚本的固定历史基线。

验收范围与尚未验证项见 `docs/superpowers/validation/2026-11-24-bug-audit-pr-validation.md`。
